# 详细设计

说明句:描述 DrawDesk 的总体架构、模块划分、核心机制与数据模型,作为实现阶段的直接依据.

---

## 一. 设计目标

本节说明设计的总体目标与依据.

---

- 依据 `README.md` 中的功能范围,第一版只实现抽屉切换、窗口隐藏、布局快照、热键、托盘与工具条
- 单进程,无服务,无网络,全部数据保存在本机
- 平台差异集中在平台层,业务逻辑保持语言无关,便于在方案 A 与方案 B 之间切换
- 所有操作可撤销,任何情况下都能一键恢复全部窗口

## 二. 总体架构

本节给出三层结构与数据流.

---

```
界面层
  Main.qml           主窗口(含搜索与详情), 悬浮窗, 按需创建独立窗口
  TrayIcon           托盘图标与菜单, Win32 Shell_NotifyIcon 实现

服务层
  DrawerService      抽屉模型, 规则匹配, 切换编排, 布局快照, 添加与移除窗口
  SelfTest           受控窗口自检, 覆盖 Cloak, 切换与布局
  HotkeyService      全局热键注册与分发

平台层
  WindowApi          枚举, 规则匹配, 显示与隐藏, 布局读写, 前台激活
  ConfigStore        配置读写, 原子写入
  SingleInstance     命名互斥体单实例
  Log                日志

数据
  %APPDATA%\DrawDesk\DrawDesk\Config.json     用户配置, 已实现
  %APPDATA%\DrawDesk\DrawDesk\Cloaked.json   当前被隐藏窗口的状态, 正常退出时删除
  %APPDATA%\DrawDesk\DrawDesk\Logs\          日志, 已实现
```

- 依赖方向自上而下,服务层不直接调用 Win32,平台层不含业务规则
- 所有窗口相关调用集中在平台层,便于集中处理失败,权限与日志
- 数据根目录默认 `%APPDATA%\DrawDesk\DrawDesk`,可由环境变量 `DRAWDESK_DATA_DIR` 覆盖;
  开发与测试时运行脚本将其指向项目内 `Build\DevData`,不写入系统目录

## 三. 代码组织

本节给出建议的目录结构与模块对应关系.

---

```
DrawDesk\
├─ README.md           产品概念
├─ Docs\               设计与计划文档
├─ Src\                源码
│  ├─ Platform\        平台层
│  ├─ Services\        服务层
│  ├─ Models\          数据模型
```

- 每个模块包含 Readme 与 Test.md 结果记录,测试文件放在 `Tests\` 对应模块下

## 四. 核心机制设计

本节描述关键行为的具体做法.

---

### 4.1 窗口识别

- 匹配规则:进程名精确匹配,可选进程 PID,窗口标题按字面或正则匹配,各项按与关系组合
- 每个抽屉独立判断窗口是否匹配自身规则,同一窗口可以同时出现在多个抽屉中
- 窗口归属完全由配置中的规则决定,不使用会话级句柄归属表
- 标题默认按字面精确匹配;规则编辑中可显式开启正则,避免字面标题里的符号被当成正则导致窗口串位
- 对 ApplicationFrameHost 承载的窗口,当前按外层窗口处理
- 无法匹配的窗口不自动归组, 由用户手动加入抽屉

### 4.2 窗口隐藏与显示

- 使用 DWM 隐藏,即 `DwmSetWindowAttribute` 的 `DWMWA_CLOAK` 属性,隐藏后窗口仍在运行,但不出现在屏幕,任务栏与 Alt+Tab
- 显示时写回 `FALSE`;使用 `DwmGetWindowAttribute` 的 `DWMWA_CLOAKED` 查询当前状态
- 不使用移出屏幕或隐藏父窗口等替代方案,原因是任务栏残留,还原闪烁与恢复困难
- 调用失败时回退到 `ShowWindow` 并记录日志,恢复时用 `SetWindowPos` 与 `RedrawWindow` 强制刷新,减少 DWM 残影
- 批量恢复分批执行,并调用 `DwmFlush` 等待合成队列,避免一帧内处理过多窗口
- `ApplicationFrameHost` 承载的 UWP 窗口不参与管理,避免其不稳定的 Cloak 行为影响桌面

### 4.3 抽屉切换流程

按以下顺序执行,单步失败不中断后续步骤.

---

1. 保存当前抽屉窗口的布局
2. 隐藏当前抽屉的全部窗口
3. 显示目标抽屉的全部窗口
4. 恢复目标抽屉的布局,显示器不存在时按回退规则放置
5. 更新界面选中态与抽屉快捷键

### 4.4 布局快照

- 记录内容:窗口匹配键, 恢复矩形与显示状态, 即正常, 最大化或最小化
- 保存时机:每次切换前自动保存, 当前没有手动保存按钮
- 恢复策略:按原坐标恢复;坐标不在任何显示器内时移动到主显示器工作区
- 分辨率或缩放变化时,以窗口可见为优先,不做精细换算

### 4.5 全局热键

- 使用 `RegisterHotKey` 注册,消息在主窗口循环中处理
- 前缀固定为 `Ctrl+Alt`;每个抽屉可单独配置数字, 字母或符号键位
- 加入当前抽屉默认 `Ctrl+Alt+Z`, 从当前抽屉移出默认 `Ctrl+Alt+X`
- 恢复全部为主窗口按钮, 窗口搜索为主窗口内输入框, 不再占用全局热键
- 注册冲突时保存后检查注册结果, 被占用的组合在界面提示更换

### 4.6 托盘与悬浮窗

- 托盘菜单包含:显示/隐藏悬浮窗与退出;左键托盘图标打开主窗口;主窗口内提供搜索, 加入移出, 显示全部与抽屉快捷键配置
- 退出流程必须先恢复全部被隐藏窗口,再结束进程
- 悬浮窗常驻置顶,仅用于快速切换抽屉,支持拖动并记忆位置;边缘吸附与右键抽屉菜单为后续优化
- 界面使用 Qt Quick 与 QML 实现;视觉效果为轻量现代风格,无边框,圆角与半透明在 Windows 11 启用,Windows 10 降级;技术路线见 `TechStack.md` 的界面技术路线一节

### 4.7 已知边界

本节列出第一版明确接受限制的场景.

---

| 边界 | 表现 | 第一版处理 |
|---|---|---|
| 管理员权限窗口 | 隐藏与移动失败 | 记录并提示,不强制提权 |
| UWP 窗口 | 外层属于 ApplicationFrameHost | 按外层窗口处理 |
| 全屏独占程序 | 切换时可能闪烁或失败 | 提示用户手动处理 |
| 显示器拔插与缩放变化 | 布局坐标失效 | 回退到主显示器可见区域 |
| 程序被强制结束 | 窗口保持隐藏 | 重启后点击显示全部或按恢复快捷键 |

### 4.8 紧急恢复脚本

- 隐藏窗口时把窗口句柄, 进程号, 进程名与标题写入 `Cloaked.json`
- 正常恢复或退出时删除该文件;程序被强制结束时会保留
- 程序无法启动时, 执行安装目录下的 `RestoreAll.ps1`, 优先按句柄恢复, 其次按进程号与标题匹配, 只处理状态文件中记录过的窗口
- 脚本不依赖 DrawDesk 主程序, 使用纯 Win32 调用取消 Cloak 并显示窗口
- 默认只处理状态文件中记录过的窗口;`-All` 参数可强制尝试所有带标题的 Cloak 或隐藏窗口, 用于状态文件丢失的极端情况

## 六. 非功能指标

本节给出可度量的目标值,作为验收依据.

---

- 空闲内存占用:Qt 方案目标 60 至 90 MB, 打包阶段实测校准
- 空闲 CPU 占用:无轮询设计,应接近 0
- 抽屉切换耗时:100 个窗口以内不超过 500 毫秒
- 冷启动到托盘就绪:不超过 2 秒
- 日志保留:最近 7 天, 由用户按需手工清理

## 七. 验收标准

本节对应第一版最小可用目标,即 `Roadmap.md` 中 M1 至 M4 全部通过.

---

- 至少 3 个抽屉,每个抽屉至少 3 个窗口;切换后任务栏与 Alt+Tab 只显示当前抽屉窗口
- 隐藏与显示 100 次无失败,无闪烁残留
- 布局恢复后窗口位置与保存时一致;显示器变化时窗口仍可见
- 强制结束进程后重启,可以一键恢复全部窗口
- 安装包在干净的 Windows 10 与 Windows 11 环境完成安装,运行与卸载
